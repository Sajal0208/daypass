Why it is safe

The role's grants are the wall; the rest are fences.
DB roleWALLSELECT on visible columns only, granted table by table, no write privilege anywhere. PII columns are hidden by Postgres, so SELECT * on those tables fails. Views that would expose a hidden column are not granted.
No stored passwordFENCEOn AWS RDS the role logs in with a 15-minute IAM token minted from your own AWS identity.
Real parserFENCEPostgres's own parser (libpg-query). One SELECT or EXPLAIN, at most 256 KiB. No data-modifying CTE, FOR UPDATE, pg_sleep, dblink, set_config, …
Read-only txnFENCEEach call in BEGIN READ ONLY, 10 s timeout or the lease time left, then DISCARD ALL.
Result capsFENCE500 rows, 2000 characters per cell, 1 MB per result, cut in the database before rows are sent.
AuditFENCETwo JSON lines per call in ~/.daypass/audit.jsonl: one before the query runs, one when it ends.
NetworkFENCEOptional: your current IP in the DB security group for the lease only, removed on close or expiry.
TLSFENCEAlways verified. RDS targets pin the bundled AWS RDS CA.
