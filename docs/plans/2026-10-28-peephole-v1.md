# Peephole v1 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A CLI + MCP server that gives a Claude Code session a time-boxed, read-only, logged window onto the prod Postgres database.

**Architecture:** One npm workspace with `core` (pure SQL guard + audit format, no I/O), `cli` (lease file, AWS IAM token, security-group IP rule), and `mcp` (stdio MCP server exposing four read tools, refuses without a live lease). Design: `docs/plans/2026-10-28-peephole-design.md`.

**Tech Stack:** TypeScript (ESM, Node 22+), `vitest`, `pg`, `libpg-query`, `@modelcontextprotocol/sdk`, `@aws-sdk/rds-signer`, `@aws-sdk/client-ec2`, `commander`.

---

### Task 1: Workspace scaffold
Create `package.json` (workspaces `packages/*`), `tsconfig.base.json`, `.gitignore`, `README.md`. Commit.

### Task 2: `core` — SQL guard (TDD)
- Test: `packages/core/test/guard.test.ts` — allows `SELECT`, `WITH ... SELECT`, `EXPLAIN SELECT`; rejects multiple statements, `INSERT/UPDATE/DELETE/TRUNCATE/DROP/ALTER/CREATE/GRANT/COPY`, `SELECT ... FOR UPDATE/SHARE`, `EXPLAIN ANALYZE`, `pg_sleep`, `dblink`, `pg_read_file`, `lo_import`, `pg_terminate_backend`, `set_config`, `SET`, `DO`, empty input, parse errors.
- Impl: `packages/core/src/guard.ts` — `checkSql(sql): {ok:true, kind:'select'|'explain'} | {ok:false, reason}` using `libpg-query` `parse`, walking the AST for `FuncCall` names and `LockingClause`.
- Commit.

### Task 3: `core` — result shaping + audit record (TDD)
- `wrapWithLimit(sql, max)` → `SELECT * FROM (<sql>) peephole_q LIMIT max+1` (not for EXPLAIN).
- `shapeRows(rows, {maxRows, maxCell, maxBytes})` → `{rows, truncated, note}`.
- `AuditEvent` type + `formatAudit()`.
- Commit.

### Task 4: `cli` — lease + config
- Config file `~/.peephole/config.json`: `{ targets: { prod: { host, port, database, user, region, securityGroupId, awsProfile } } }`.
- Lease file `~/.peephole/lease.json`: `{ id, target, reason, openedAt, expiresAt, ip }`.
- `peephole open <target> --ttl 60m --reason "..."`, `status`, `close`, `log --last N`.
- `open` adds the caller's public IP to the security group (tag description `peephole:<leaseId>`), `close`/expiry removes it. `sweep` removes any `peephole:*` rule older than its lease.
- Commit.

### Task 5: `mcp` — server
- Tools `list_tables`, `describe_table`, `query`, `explain`. Each: read lease → if expired/missing, return error text. Get IAM token via `Signer` (cache 10 min). `pg.Pool` max 2, with `options: '-c default_transaction_read_only=on -c statement_timeout=30000'` as belt-and-braces. Run guard, wrap, shape, append audit line to `~/.peephole/audit.jsonl`.
- Commit.

### Task 6: DB setup SQL + docs
- `sql/setup-role.sql`: create `peephole_ro`, `GRANT rds_iam`, schema/table SELECT grants, `ALTER ROLE ... SET` timeouts, column revokes list from config, `CONNECTION LIMIT 5`.
- README: install, one-time setup, `claude mcp add`, daily use.
- Commit.

### Task 7: Smoke against local DB (`localhost:5434`), then prod with user present.
